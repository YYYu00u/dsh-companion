# @dsh-companion/voice

Local, offline voice for the companion. ZipVoice zero-shot cloning, served on `127.0.0.1` and used by the web room's click-to-play button.

## Status

Beta. The engine and page are wired; the model and reference audio are **not** in the repository.

- Model: about 197 MB, downloaded by `npm run models`.
- Reference audio: generated by `npm run refs` with your own Volcengine key; not redistributable here.
- Synthesis: 8 steps by default, roughly 15–60 s per sentence on an M2 CPU; `steps: 16`/`32` is available but slower. Not suitable for real-time calls.

## Setup

```bash
cd packages/voice
npm run models                 # download ZipVoice int8 + vocoder, verify sha256
VOLC_KEY=xxx npm run refs      # generate the reference wavs (needs ffmpeg)
python3 -m pip install -r runtime/requirements.txt
```

Then install the bundle in DSH. The default config starts the local server on port 4321.

## API

- `POST /tts` — `{text, voice}` → `audio/wav`
- `GET /health` — readiness and the voice ids
- `GET /api/voices` is exposed by the web package, not this one.

The companion web host can cache text + voice pairs in `<home>/.data/tts-cache/`; that cache lives in the host, not in this package.

## Why the wav files are not here

The reference clips are generated from a commercial TTS voice. The ids and the reference text are in `assets/voices.json`; each user generates their own wav files. Do not commit `.wav`, `.models/`, or `.venv/`.
