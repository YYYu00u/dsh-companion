# v0.3.0 — voice and ears

> Documentation corrected in v0.3.1. The public packages do not ship the private deployment's voice-bubble/TTS-cache UI.

This release adds the two senses the companion was missing: a local voice and a push-to-talk ear. Both are beta and both keep their models out of the repository.

## Highlights

- **`@dsh-companion/ears`** — hold-to-talk system audio, microphone, or an audio file; local sherpa-onnx + SenseVoiceSmall turns it into text. The macOS helper is Objective-C/ScreenCaptureKit; no BlackHole or screen-recording driver.
- **`@dsh-companion/voice`** — ZipVoice zero-shot voice with a local TTS server and a click-to-play page. Reference wavs and the 197 MB model are generated/downloaded by the user, not shipped.
- **Electron window** — fish icon, app title, and history that opens at the bottom.
- **Web room** — optional listen button, hidden unless the ears Host is present.
- **Private deployment only for now** — hold-to-talk voice messages, WeChat-style voice bubbles, and a persistent TTS cache; the public packages do not ship that UI yet.

## Verified numbers

| Check | Result |
|---|---|
| Unit/smoke tests | 48 passing |
| `npm run check` | clean (syntax, manifests, private paths, secrets) |
| SenseVoice | 4.2 s system audio → text in ~0.9 s on M2 |
| Ears endpoint | `GET /ears/api/status` → 200, helper + model present |
| TTS | `/api/say` returns 24 kHz mono WAV; first load ~10 s, cached replay instant |

## Install

See [docs/install.md](../install.md). Ears can be installed as a Host bundle (pet menu + `/ears/api/*`) and, optionally, as a preset row for `listen_now` / `listen_file`.

## Known limitations

- Ears: song ID and a full web voice-message UI are still pending; no always-on listening.
- Voice: CPU-only; 8-step synthesis is 15–60 s per sentence, not suitable for calls.
- Both features are marked **beta** in [docs/verification.md](../verification.md).
